## 1. 项目是什么

**年轮**是一个纯本地离线的私人时光容器 App（仅 Android）：

- 一切数据以「**某一天**」为节点组织：**照片 + 日记 + 音乐** 三者绑定到一天
- **双入口殊途同归**：从星河点开一张照片 → 落到它拍摄的那一天；从日历点开某一天 → 落到同一个节点页
- 节点页 = 灵魂所在，两个形态：
  - **沉浸态**（默认）：全屏照片 + 虚化氛围背景 + 旋转唱片机；**进入时音乐自动淡入**
  - **翻书态**（上滑切换）：3D 翻页的纸质书，日记一页一篇、照片是拍立得页；**音乐贯穿两态不中断，退出时淡出**
- 无云端、无账号、无广告；数据全部存应用沙盒，支持一键导出/导入 `.nianlun` 备份文件

| 决策点 | 结论 |
|--------|------|

## 3. 架构分层

```
┌─────────────────────────────────────────────┐
│ UI 层  pages/                                │
│  home(星河) calendar(日历) node(节点页⭐)      │
│  editor(日记编辑器) settings(备份)             │
├─────────────────────────────────────────────┤
│ 状态层  providers/app_providers.dart         │
│  db → dayRepository → days / dayEntry(family)│
│  各 service provider + refreshAllDays()      │
├─────────────────────────────────────────────┤
│ 业务服务层  services/                         │
│  photo_import / media_attach / audio / backup │
├─────────────────────────────────────────────┤
│ 数据层  database.dart + day_repository.dart  │
│  SQLite v2 + 文件系统（媒体沙盒目录）           │
├─────────────────────────────────────────────┤
│ 基础设施  models / theme / utils / widgets   │
└─────────────────────────────────────────────┘
```

**数据流向（单向）**：UI 触发 service → service 写 DB/文件 → `refreshAllDays(ref)` 使 providers 失效 → UI 自动重建。

### 数据库 schema（v2）

```sql
days(id, date_key, mood)                      -- 一天一行，mood 可空
photos(id, day_id, relative_path, taken_at,
       dominant_color, width, height,
       source_id, caption, sort_order)         -- width/height/source_id 为 v2 新增
journals(id, day_id, content, created_at, updated_at)
music(id, day_id, title, artist, relative_path, source_url)
```

媒体文件存应用沙盒 `media/` 目录（照片/音乐按相对路径引用，备份时可整体迁移）。

## 4. 关键设计决策（为什么这么做）

1. **双入口落同一页**：星河点照片带 `initialPhotoIndex` 直接定位到那张；日历点某天进同一 `NodePage(date)`——需求的核心承诺。
2. **音乐贯穿双态**：沉浸态/翻书态是同一个 NodePage 内部状态切换，PlayerService 实例不销毁，所以音乐不断。
3. **照片存沙盒副本**：导入即复制进应用私有目录，系统相册删原图不影响年轮；`source_id` 去重防重复导入。
4. **EXIF 归天**：拍摄时间 > 文件修改时间兜底；EXIF 旋转标记（5~8）时**以实际解码画面的横竖为准**，否则横竖判断错位引发排版怪象。
5. **横图翻书动画**：`Transform.rotate + Transform.scale`（照片基准尺寸固定，动画只变矩阵）；
   `endScale = max(ar, cardH/cardW)` 保证旋转 90° 后刚好铺满卡片；动画进度直接绑 PageController（手指停动画停）。
6. **静态 ThemeData**：`StarryTheme.dark/paperLight` 必须 `static final`——键盘动画期间每帧新建 ThemeData 是此前卡顿的主凶。
7. **键盘避让**：编辑器页用独立 `_KeyboardAvoider`（只有它依赖 viewInsets）+ `MediaQuery.removeViewInsets`，键盘动画只重建薄薄一层。
8. **终端限制下的工作流**（见 §5）：Agent 改代码 + LSP 自检；构建/装机由人在 cmd 跑脚本。

## 5. 开发环境与构建（Windows）

### 一次性环境

1. Flutter SDK → `D:\Dev\flutter`（加入 PATH）
2. Android SDK → `D:\Dev\android-sdk`（platforms 34/35/36 + build-tools）
3. 环境变量：`PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`
4. Windows **开发者模式**开启（Flutter plugin 需要 symlink 支持）
5. （强烈建议）给 `D:\Dev` 和项目目录加 **Windows Defender 排除**——不排除时 Gradle 构建能慢 5~10 倍（曾出现 49 分钟构建）

### 日常构建

双击仓库根 `一键初始化构建.cmd`（纯 ASCII，4 步）：版本检查 → pub get → analyze → assembleDebug。

- APK 产出：`build/app/outputs/flutter-apk/app-debug.apk`（debug 约 190MB 属正常）
- ⚠️ **不要再跑 `flutter create`**——平台目录已手工配置（compileSdk 36 等），create 会覆盖
- 仓库只含 android/；如需其他平台：`flutter create --platforms=web,ios,linux,macos,windows .`

### ⚠️ WorkBuddy/AI 终端限制（重要经验）

在某些 AI 终端里 **Dart 无法派生子进程**（CreateFile 231 错误），所以：

- flutter / dart / gradle 命令**必须由人在真实 cmd 里跑**
- `.cmd` 脚本必须**纯 ASCII**（文件名可中文，内容不行，否则乱码）
- 项目路径必须**纯 ASCII**（所以仓库叫 `nianlun` 而不是「年轮」）
- 静态检查用 **LSP 直连**方案：`dartaotruntime.exe` 跑 `analysis_server_aot.dart.snapshot`，Python 走 LSP 协议对话（脚本在开发机 `D:\A_WorkBuddy_Project\年轮\.workbuddy\tools\lsp_check.py`，也固化在技能 `~/.workbuddy/skills/flutter-windows-agent-build/`）

## 8. 附：修复经验沉淀（防止重蹈覆辙）

- **ThemeData 必须 static final**，getter 会在每帧 build 时构造新对象，键盘动画期间掉帧严重
- **旋转+放大的图片，解码分辨率按"最终视觉尺寸 × DPR"算**，cacheWidth 固定值必糊
- **动画驱动**优先 `Transform`（只改矩阵）而不是每帧改子组件尺寸（会触发 Image 重 layout）
- **Quill 11.x**：`QuillEditor.basic(controller:, config: QuillEditorConfig(...))`；localizations delegate 必须挂 MaterialApp
- **EXIF 横竖**：`ImageDescriptor` 的宽高不一定等于解码后画面横竖，以 `ui.Image` 为准
- **音频播放顺序**：setFilePath → 等 ProcessingState.ready → play；错误不要静默吞，要给用户可见反馈
